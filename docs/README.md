# hype-trigger-twap 日本語ドキュメント

Hyperliquid 無期限先物向けの「トリガー付き TWAP」を実行する単一 Rust バイナリ (`hype-twap`) の
日本語資料です。サーバー・WebSocket・Python・DB は一切使いません。

指定した価格または経過時間で発火し、目標数量を等間隔の IOC (テイカー) スライスに分割して
執行します。スライスが約定不足のときは次スライスで自動的に取り返します (キャッチアップ方式)。

**Read-only (ドライラン) が既定値です。** `--read-only false` を明示しない限り注文は一切送信されません。

## 最短の使い方

```bash
# ビルド
cargo build --release

# ドライラン (既定) — 実際には発注せず、板から計算した想定注文を表示
./target/release/hype-twap --symbol HYPE --side long --usd 1500 --duration 30m

# 本番実行
export HL_AGENT_PK=0x<64桁の16進数>
./target/release/hype-twap --symbol HYPE --side long --usd 1500 --duration 30m --read-only false
```

## 安全設計の要点

このツールは実資金を扱うため、以下を既定の振る舞いとしています。

- **既定はドライラン** — `--read-only false` を明示するまで署名も送信も行いません
- **不明な銘柄は起動時に停止** — 発注前に `/info meta` と照合します
- **取引所の拒否は即時停止** — 証拠金不足・最低数量割れは再試行せず全体を止めます
- **秘密鍵は環境変数のみ** — コマンドライン引数では受け取らないため、シェル履歴や `ps` に残りません
- **曖昧な送信は cloid で照合** — 応答が失われた注文は再送前に実際の状態を問い合わせ、二重約定を防ぎます

## Hyperliquid 組込み TWAP との使い分け

Hyperliquid には取引所側で動くネイティブ TWAP 注文 (UI の「TWAP」タブ / API の `twapOrder`) が
あります。一度発注すれば手元にプロセスを保持する必要がなく、多くの用途ではそちらで十分です。
本ツールはネイティブ TWAP がカバーしない領域のために存在します。以下のネイティブ側仕様は
[公式ドキュメント](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/order-types)で
確認できた事実のみ記載しています (記載のない挙動は「非公開」であり「無い」とは限りません)。

| | ネイティブ TWAP | `hype-twap` |
|---|---|---|
| 実行主体 | 取引所側 (発注後は手元プロセス不要) | 手元マシン (実行中はプロセス常駐、障害時は `--resume` で復旧) |
| サブオーダー間隔 | 最小30秒・サイズ÷期間から自動算出 (間隔の直接指定不可) | `duration / slices` で自由に設定 (下限は $10/スライスの最小注文額) |
| 期間・金額の範囲 | 5分〜7日、合計 $100 以上 | 期間任意、合計 $10×スライス数 以上 |
| スリッページ | 固定 3% 上限 | `--slippage-bps` (既定 20bps、1000bps 超は警告・10000bps 以上は拒否) |
| 約定不足の取り返し | 後続サブオーダーが最大3倍まで拡大 (追い付けない場合あり) | 不足分を全量、後続スライスへ繰越 |
| トリガー | Trigger Price で開始 / Max・Min Price で終了 (マーク価格基準) | 価格 (`--trigger-price`) と時間 (`--start-after`) の OR、`--expire-after` で未発火なら何も置かず終了 |
| メイカー執行 | post-only オプションの記載なし (アップグレード中の post-only 期間には約定しない = テイカー挙動) | `--child-algo passive` で ALO 指値 (メイカー手数料) |
| サイズランダム化 | オプションで各サブオーダー ±20% | なし (スライスは均一) |
| 追加の安全装置 | 取引所の証拠金チェック | `--max-notional-usd` 必須 (live 時)、既定 read-only ドライラン、毎スライス前の板検証 |
| 第三者からの見え方 | TWAP として識別可能 (`userTwapSliceFills` で任意アドレスの TWAP 約定を誰でも照会可) | 通常の IOC/ALO 注文 (約定自体はアドレス単位で公開されるが TWAP とはラベルされない) |
| 監査証跡 | API 経由の取引所側履歴 | ローカルの fsync 済み JSONL ジャーナル + 最終レポート |

**ネイティブ TWAP が向くケース**: 発注しっぱなしにしたい / マシンの稼働時間より長い窓で執行したい /
サブオーダーのランダム化が欲しい。

**本ツールが向くケース**: 30秒未満や正確な刻みのスライス間隔 / 価格 OR 時間トリガーと待機打切り
(`--expire-after`) / メイカー (post-only) 執行 / 3% より厳しいスリッページ管理 / $100 未満の小口 /
実行前に同一計画のドライラン / TWAP とラベルされない注文フロー / 送信内容のローカル完全記録。
